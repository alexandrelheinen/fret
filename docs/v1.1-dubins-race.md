# v1.1 — Dubins Dual-Robot Race (Implementation Guide)

> **Release:** v1.1 · **Scenario:** SC-v11 (`dubins_race`) ·
> [releases.md](releases.md#v11--dubins-dual-robot-race)

This document is the step-by-step implementation plan for v1.1. It mirrors
the v1.0 PPP warehouse pipeline while adopting the ARCO `vehicle` race format
(RRT* vs SST, Pure Pursuit tracking, shared occupancy map).

---

## 1. Goal

Two **Dubins car-like robots** race from corner **A** (lower-left) to corner
**B** (upper-right) through a **warehouse column forest** rendered in MuJoCo.
Unlike the ARCO `vehicle` benchmark (a short maze with a single mid-field wall
gap), this scenario deliberately leaves **multiple viable routes** so RRT* and
SST can choose different paths.

| Agent | Planner | Visual identity |
|---|---|---|
| Car 1 | ARCO RRT* | Blue chassis (`layer_rgb("rrt", "vehicle")`) + marker **1** |
| Car 2 | ARCO SST | Green chassis (`layer_rgb("sst", "vehicle")`) + marker **2** |

No external car mesh is required. Each Dubins agent is a compact chassis:

- Body: box `0.72 × 0.44 × 0.18` m
- Four wheel cylinders (visual only)
- Roof marker disc (white = agent 1, dark = agent 2) for algorithm ID at a glance

Planning and control use ARCO directly — no URDF import.

## 3. Environment design

### 3.1 Workspace (shorter than ARCO 50 m × 50 m)

| Axis | Range | Notes |
|---|---|---|
| X | 0 – 24 m | Aisle length |
| Y | 0 – 16 m | Bay width |
| Z | 0 – 4 m | Column heights vary 1.8 – 3.8 m |

Start **A** ≈ `(2, 2)` m, goal **B** ≈ `(22, 14)` m.

### 3.2 Column forest (not a maze)

Obstacles are **scattered circular columns** (planning radius ≈ 0.5 m) in
**staggered rows** with deliberate gaps:

1. **South corridor** — open band along `y ≈ 1.5–3.5` from A toward centre.
2. **Central weave** — offset columns around `(10–14, 7–11)` with ≥ 2 m gaps.
3. **North approach** — columns thin toward B; north-east corner kept open.

This yields at least three qualitatively different routes (south→east→north,
diagonal through centre, west→north→east) without a single choke-point wall.

### 3.3 Occupancy model

Port ARCO `vehicle.py` pattern:

```python
KDTreeOccupancy(column_centres, clearance=vehicle_radius + margin)
```

2-D planning in `(x, y)`; heading handled at execution by Pure Pursuit +
`DubinsVehicle`.

## 4. Pipeline (same structure as v1.0 PPP)

```
Obstacle YAML → KDTreeOccupancy
                     ↓
         RRT* plan (agent 1)     SST plan (agent 2)
                     ↓
         TrajectoryPruner (optional, per path)
                     ↓
    Pure Pursuit + DubinsVehicle × 2  (ARCO TrackingLoop)
                     ↓
         DubinsRaceBridgeCore → MJCF state sync
                     ↓
         Race metrics (time-to-goal, path length, winner)
```

Pure-Python orchestrator: `fret.scenario.dubins_race_runner.DubinsRaceRunner`
(analogous to `PPPWarehouseRunner`).

ROS SITL launch (`sitl.py scenario:=dubins_race model:=dubins backend:=mujoco`)
loads the MuJoCo scene; full dual-agent ROS graph is a follow-up once the
pure-Python E2E path is green in CI.
