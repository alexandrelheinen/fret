## Overview

**Seeed SO-ARM101 Pro** (SO-101 follower) — 5 revolute DOF + a 1-DOF friction
gripper, Feetech STS3215 USB smart servos, no onboard firmware. Chosen as the
v2.x hardware target in PR2 (`v2.0.0`); see
[`arm-selection.md`](../hardware/arm-selection.md) for the full decision
record (requirements, candidates, scored comparison, known risks).

The model comes from MuJoCo Menagerie's `robotstudio_so101/`, vendored
directly under `third_party/robotstudio_so101/` (not a submodule — see that
directory's `IMPORTED_ASSETS.md` for why and the pinned upstream commit).

PR2 ships the **simulation twin**:

1. **SC-v20a** (`so101_reach`) — empty tabletop, end-effector pose A → B
   under full MuJoCo physics (FR-SIM-20: ≤ 5 mm EE error at the goal).
2. **SC-v20b** (`so101_pick_place`) — known-pose pick-place in friction
   grasp *mode* (FR-SIM-18): no MuJoCo adhesion actuator; hold uses a
   contact-gated equality weld (see `docs/decisions.md`).
3. **SC-v20c** (`so101_pick_place_cv`) — overhead-camera vision pick-place
   (FR-SIM-19).
4. **SC-v20d** (`so101_wall_maze`) — the same pick and release segment,
   with a dual Γ the arm has to back out and climb over.

Unlike `OpenManipulatorXKinematics` / `OpenManipulatorYKinematics` (which
evaluate FK/IK on a live MuJoCo model), SO-101 kinematics are **pure NumPy**
(`fret.control.kinematics_so101`) and never import `mujoco`: the Raspberry
Pi 5 runtime has no MuJoCo (GAPS G2, PR5). The fixed per-body transforms are
hardcoded constants derived from the vendored MJCF by
`scripts/gen_so101_kinematics.py --check`.

## Joints

| Joint | Role | Hard range (vendored MJCF) |
|---|---|---|
| `shoulder_pan` | Base slew | ±1.91986 rad (±110°) |
| `shoulder_lift` | Shoulder | ±1.7453293 rad (±100°) |
| `elbow_flex` | Elbow | ±1.69 rad (±96.8°) |
| `wrist_flex` | Wrist pitch | ±1.658063 rad (±95°) |
| `wrist_roll` | Wrist roll | −2.7438473 … +2.8412063 rad |
| `gripper` | Friction jaw | −0.174533 … +1.7453292 rad |

`fret.control.kinematics_so101.SO101Kinematics` covers the first 5 joints
(the ones that move the `gripperframe` end-effector site); the gripper joint
is handled by grasp logic, not kinematics — the same split as
`OpenManipulatorXKinematics` excluding `Gripper`.

**Reach:** workspace radius 0.10–0.32 m at table height (FR-SIM-17); SC-v20a
uses a wide `shoulder_pan` sweep at a fixed reach posture for the other four
joints (~0.69 m XY travel), well inside every joint's hard range.

## Actuation (sim twin)

The vendored MJCF uses MuJoCo `<position>` actuators (`sts3215` class,
`kp=998.22`, `kv=2.731`) — the same actuator family the real Feetech bridge
drives in position mode (PR3). FRET keeps velocity commands on
`/joint_commands` (Q3, decided 2026-11-17);
`fret.control.velocity_to_position.VelocityToPositionIntegrator`
(FR-CTL-07) converts them to position goals in both the twin and the real
bridge in PR3, so the two share the exact same conversion code.
